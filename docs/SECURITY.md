# Security controls and threat model

## Intended first-release trust boundary

DPN DS v0.1 is an **evaluation build**, not a production-ready AD administration plane.

1. Bind backend to 127.0.0.1 only. Do not port-forward it or expose it directly to the internet.
2. All /api/v1 routes require a high-entropy DPN_DS_API_TOKEN, generated by the operator and set in the environment (never in Git, browser bundles, logs, or URLs).
3. Serve UI/API through the same trusted HTTPS reverse proxy if accessed remotely. Configure access control and MFA at the proxy. No wildcard CORS.
4. Samba CLI operations are read-only allowlisted arguments. Never accept user-provided shell commands, arguments, or paths.
5. Demo mode is opt-in and clearly shown. It must not look like live domain telemetry.
6. Running Samba utilities may require elevated local permissions. **Do not run a root-owned, internet-facing FastAPI service.** A least-privilege, separately isolated adapter is a production blocker.
7. Never put admin passwords on the command line. Protect Kerberos tickets and machine credentials.
8. Audit access to the reverse proxy and server. Protect domain controller backups and secure DNS / NTP.
9. Domain controllers should remain dedicated to authentication, not general web hosting.

## Phase 4 additions

OIDC-issued access tokens may be verified with operator-pinned public key, issuer/audience, signed MFA assertions, and server-enforced monitoring roles. No browser login/PKCE is provided. Every directory API request emits a sanitized security event to the application logger, but immutability, central forwarding and retention are not yet provided.

## Known remaining gaps

- Static operator bearer token, not OIDC or per-user RBAC; no rotation workflow.
- No API-specific rate limiting, audit storage, CSRF model for future writes, or privileged agent separation.
- Domain availability checks are local systemd status, not actual replication/DNS/Kerberos validation.
- Dependencies have ranges in v0.1. Lockfiles, supply-chain review and SBOM are planned.
- No authorization boundary for directory **writes**, since none are implemented.

## Reporting

Open a private security advisory or contact the DPN maintainers privately. Never attach active credentials, domain dumps, or secrets to public issues.
